# 博客文档生成 Skill

## 执行前必读

开始任何步骤前，先读取以下参考文件：
- **文档模板**：`references/doc-template.md` — 完整的 Frontmatter + 正文结构模板
- **质量标准**：`references/quality-rubric.md` — SEO/GEO 检查项 + 评估评分表

---

## 工作流（5 步，严格顺序执行）

### Step 1 · 主题研究

**目标**：收集足够的素材，不依赖训练数据写作。

执行 **≥4 次** `web_search`，必须覆盖四个角度：

| 搜索角度 | 关键词模式 | 用途 | 执行条件 |
|----------|-----------|------|----------|
| 核心概念 | `{主题} 原理 概念 定义` | 权威定义 | 必须执行 |
| 最新进展 | `{主题} 2025 最新 趋势` | 时效性信息 | 必须执行 |
| 权威来源 | `{主题} arXiv 论文 官方文档` | 可引用的一手资料 | **视情况**：概念/原理类主题执行；纯代码演示类主题可跳过 |
| 实践案例 | `{主题} 教程 示例 最佳实践` | 具体应用场景 | 必须执行 |

研究产出（内部整理，不输出给用户）：
- 2-3 个权威定义
- 核心知识点列表
- 论文/文档链接（有则整理，无则不强求）
- 1-2 个实际应用案例（**优先收集可直接运行的代码示例**）

---

### Step 2 · 内容编写

**目标**：依据研究结果，按模板写出完整初稿。

**文件命名**：
- 文件名：简洁中文，如 `为什么RAG要使用向量数据库.md`
- 主题简称：2-4 个英文关键词用连字符，如 `rag-vector`（用于图片 CDN 路径）
- 保存路径：`{当前工程目录}/docs/{文件名}.md`

**写作原则**（必须全部遵守）：

1. **实用优先**：内容以"读者能立刻用上"为核心导向；理论解释服务于实践，不为覆盖知识点而堆砌。每个概念必须跟进"怎么用"或"用在哪"
2. **问题先行**：用一个具体场景/痛点开篇，让读者先理解"为什么"
3. **生活类比**：每个抽象概念配一个类比（如"向量 = 菜品的特征标签"）
4. **由浅入深**：章节顺序严格按 动机/背景 → 核心概念 → 运作机制 → 代码实现 → 最佳实践 → 变体/进阶（可选）→ 横向对比（可选）→ 总结 推进，不跳层次；代码实现和最佳实践章节权重优先于理论进阶
5. **章节名称 topic 化**：H2 和 H3 标题必须贴合主题（如"三种核心 Agent 模式"），禁止使用通用占位名（如"深入原理讲解"）
6. **H3 是主要内容单元**：每个 H2 下必须有 2-4 个 H3 小节；每个 H3 至少包含 1 个段落 + 1 个可视化元素（表格/mermaid 图/代码块/提示框）
7. **代码优先级与规范**：代码语言优先级 **Java > JavaScript > Python**，优先使用 Java 示例；仅当 Java 不适用于该场景时（如前端、脚本场景）依次降级。所有代码必须带注释且实际可执行，关键步骤之间用注释分隔
8. **内容量化要求**：≥5 个表格，≥4 个 GitHub 提示框；正文总字数 ≥3000 字
9. **权威引用（视情况）**：
   - 概念/原理章节：可引用学术论文或官方文档，增强可信度
   - 代码演示章节：引用可忽略；若有官方 API 文档链接则附上，否则无需强求
   - 全文引用数量不设硬性下限，有则好，无也不扣分
10. **mermaid 图（视情况）**：仅在以下场景添加，不为凑数量强行插图：
    - 有明确**流程/步骤顺序**（flowchart）
    - 有**系统架构/组件关系**（graph/C4）
    - 有**时间线或阶段演进**（gantt/timeline）
    - 有**多维度层级关系**（mindmap）
    - 图表应使用 `style X fill:#...` 着色、`subgraph` 分组、emoji 标注层级

**MindMapFloat 规范**（违反视为格式错误）：

MindMapFloat 是文章的**知识维度地图**，不是章节目录。生成规则：

- 节点是**知识维度/主题分类**（如"为什么需要""关键能力""主流实现"），不是 H2 章节标题的复制
- 一级节点数量通常 4-6 个，**少于**文章 H2 章节数
- 二级节点从正文中提炼核心要点，禁止占位词
- **写作顺序**：先完成全文正文 → 再提炼 MindMapFloat 节点

完整模板 → `references/doc-template.md`

**GitHub 风格提示框速查**：
```
> [!NOTE]     补充说明
> [!TIP]      最佳实践
> [!IMPORTANT] 核心要点
> [!WARNING]  注意事项
> [!CAUTION]  常见错误
```

**arXiv 论文引用格式**（统一规范，用于 llms.txt 自动提取）：
```markdown
# 导语中核心论文（会被自动提取）：
> 📌 **核心论文**：[论文标题](https://arxiv.org/abs/XXXX.XXXXX)（arXiv:XXXX.XXXXX）

# 正文引用（不会被提取）：
[论文标题](https://arxiv.org/abs/XXXX.XXXXX)（arXiv:XXXX.XXXXX）
```

> [!IMPORTANT]
> 只有导语中 `📌 **核心论文**` 或 `📌 **原始论文**` 格式的标记才会被自动提取到 llms.txt。标记必须出现在文档开头 4000 字符以内。

完整的文档 Frontmatter + 正文结构 → 详见 `references/doc-template.md`

### Step 3 · SEO & GEO 优化

**目标**：让文章对传统搜索引擎（SEO）和 AI 搜索引擎（GEO）都友好。

完成初稿后，对照 `references/quality-rubric.md` 中的 **SEO 检查表** 和 **GEO 检查表** 逐项自查并修正。不通过的项必须立即修改，不允许跳过。

---

### Step 4 · 质量评估（最多迭代 3 轮）

**目标**：通过自评发现并修正质量问题。

**执行规则**：
- 初稿完成后执行第 1 轮评估
- 有修改意见 → 回到 Step 2 修改 → 重跑 Step 3-4
- **最多迭代 3 轮**。第 3 轮结束后无论是否有小问题，直接进入 Step 5

评估维度和评分模板 → 详见 `references/quality-rubric.md` 中的 **评估报告模板**

**迭代终止条件**：无修改意见 **或** 已完成 3 轮迭代。

---

### Step 5 · 输出检查与通知

**目标**：确认文件完整，向用户报告结果。

最终检查清单（逐项确认）：

| 检查项 | 要求 |
|--------|------|
| 文件已保存 | `docs/{文件名}.md` 路径正确 |
| Frontmatter | title / category / tags / description / keywords / cover 均填写 |
| 关于本文档 section | MindMapFloat 后存在，含 ✅ 预览清单 |
| MindMapFloat 节点真实 | 节点是知识维度（非章节标题），二级节点从正文提炼，无占位词 |
| H2 章节名 topic 化 | 无通用占位名，所有 H2/H3 标题贴合主题 |
| H3 使用 | 每个 H2 下有 ≥2 个 H3 小节 |
| mermaid 图表 | 视情况而定；如有，必须含 style 着色或 subgraph 分组 |
| 表格 | ≥5 个 |
| 代码示例 | 优先 Java，可运行，有注释，含框架真实 API |
| 权威引用 | 概念章节中如有则注明来源；代码演示章节中可忽略 |
| 正文字数 | ≥3000 字 |
| 评估报告 | 本轮报告已生成 |

全部通过后，在对话中输出以下通知：

```
✅ 博客文档生成完成！

📄 文件位置：{工程目录}/docs/{文件名}.md
🔄 评估轮次：第 {N} 轮
⭐ 综合评分：{平均分}/5

请审阅文档，如需调整请告知。
```

## 全局注意事项

- **实用为纲**：每个知识点都应给出"能立刻上手"的答案；理论是手段，实践是目的
- **面向初学者**：先解释"为什么"，再解释"是什么"和"怎么做"；避免先摆概念后才给实例
- **代码语言优先级**：Java > JavaScript > Python；优先写 Java 示例，仅在 Java 不适用时降级
- **引用原则**：概念/原理部分有一手来源（论文、官方文档）则引用；纯代码演示部分无需强求引用
- **图表原则**：流程、架构、阶段演进等有空间关系的内容用 mermaid；简单对比优先用表格，不为凑数量画图
- **有据可查**：重要技术论点有来源支撑（概念章节），代码示例使用真实框架 API
- **图片路径规范**：统一使用 `//pub.smallyoung.cn/course_slidev/{主题简称}/`
- **客观中立**：技术方案对比时列出各方优缺点，不做主观推荐
- **迭代有界**：严格执行最多 3 轮限制，禁止无限循环
